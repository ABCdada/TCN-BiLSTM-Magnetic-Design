# Model card: TCN-BiLSTM transient magnetic inference

## Summary

This repository serves five material-specific neural networks that reconstruct
the unknown portion of a magnetic-field-strength trajectory, `H`, from a
complete magnetic-flux-density window, operating information, and any available
history of `H`. The models operate on fixed 1,000-sample windows at the
reference sampling rate of 16 MHz.

The software supports one-window inference, explicit long-sequence window
stitching, a circuit-window preprocessing interface, and deterministic
converter examples. It is an inference package, not a training release or a
one-timestep constitutive solver.

## Model variants

| ID | Material | Input channels | Trainable parameters |
|---|---|---|---:|
| A | 3C92 | `B`, `dB`, `T`, `H_known`, `mask` | 497,793 |
| B | 3C95 | `B`, `dB`, `T`, `H_known`, `mask` | 2,092,545 |
| C | FEC007 | `B`, `dB`, `T`, zero `H` placeholder, `mask` | 2,092,545 |
| D | FEC014 | `B`, `dB`, `T`, `H_known`, `mask` | 2,512,593 |
| E | T37 | `B`, `dB`, `ddB`, `T`, `H_known`, `mask` | 2,092,865 |

Models A-D use five input channels. Model E is the final six-channel checkpoint
used by the accompanying manuscript and additionally uses the second discrete
flux increment, `ddB`. Derived increments and masks are constructed by the
backend. The three standard history/prediction modes are `900-100`, `500-500`,
and `100-900`.

## Architecture

The full model combines residual dilated temporal convolutions, a two-layer
bidirectional LSTM, and pointwise fully connected regression. The unknown `H`
interval is produced in one forward pass within each 1,000-point window. Model
sizes differ by material as recorded in the registry and authoritative weight
manifest.

See [the architecture diagram](docs/images/model_architecture.svg).

## Intended uses

- Reproduce the published inference interface with authorized checkpoints.
- Reconstruct masked `H` intervals for inputs that match the material,
  preprocessing, units, sampling, and operating domain of a checkpoint.
- Integrate window-level magnetic inference into research circuit workflows.
- Perform controlled software, checkpoint-integrity, and interface checks.

## Out-of-scope uses

- Treating the BiLSTM as a causal, one-timestep element in a closed-loop circuit
  solver without an external block-iteration and convergence method.
- Claiming accuracy for a new material, geometry, temperature, sampling grid,
  or excitation domain without independent validation or adaptation.
- Using the simple `B`/`H` conversion for gapped, hybrid-material, strongly
  nonuniform, or leakage-dominated structures without a suitable segmented
  magnetic network or field solver.
- Interpreting every open-window `H dB` integral as irreversible core loss.
- Safety-critical design decisions without experimental verification.

## Inputs and outputs

Inputs use SI units: `B` in tesla, `H` in ampere per metre, temperature in
degrees Celsius, voltage in volts, area in square metres, path length in metres,
and sampling rate in hertz. Each direct model call uses exactly 1,000 samples
and the sampling-rate contract is 16 MHz.

The main output is a complete reconstructed `H` trajectory plus the predicted
target interval. Circuit interfaces may additionally return reconstructed `B`,
magnetizing current, and explicitly labelled energy-related quantities.

## Energy interpretation

The discrete implementation integrates trapezoidal `H` values along increments
of `B`.

- An open-interval integral is net transient magnetic-energy exchange and may
  contain a change in stored energy.
- A closed-path integral is cumulative closed-path energy. It is loss energy
  density per cycle only when the path contains exactly one magnetic period.
- Loss density in watts per cubic metre additionally requires a valid cycle
  rate associated with the closed period.

The API keeps these concepts separate.

## Validation status

The release has 40 automated tests, 39 of which run without released checkpoint
files. They cover the registry, schema validation, checkpoint integrity,
parameter counts, forward shapes, window stitching, circuit interfaces,
converter state equations, resource-download controls, and numerical `H dB`
integration. An AutoDL CUDA verification report records strict loading and one
finite 1,000-point forward pass for every checkpoint.

These checks establish software and artifact integrity. They do **not**
reproduce the manuscript's accuracy metrics. Files generated by
`scripts/generate_sample_inputs.py` are deterministic synthetic smoke-test
inputs and are not experimental evidence or benchmark results.

## Limitations and risks

- Performance depends on the exact checkpoint, normalization state, material,
  data domain, and acquisition conditions.
- Long-sequence prediction is explicit window stitching; errors may propagate
  between windows and the model is not proven invariant to arbitrary sequence
  length.
- The model is not inherently invariant to sampling interval. Data collected on
  another grid require appropriate rate features and retraining or fine-tuning.
- Sensor offset, voltage-integration drift, synchronization, anti-aliasing,
  geometry uncertainty, and domain shift can degrade deployment performance.
- Material C follows its training convention of a single raw zero placeholder
  for historical `H`; it must not be silently treated like the other materials.
